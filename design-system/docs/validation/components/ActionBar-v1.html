Modèle Action et ActionBar — v1 VALIDÉ le 2026-11-23

Spec prévue : src/patterns/ActionBar/ActionBar.spec.md. Proposition P2 (lot 1). Une app décrit ses actions par des données ; une règle de Socle choisit leur forme selon la zone. Version mineure : un export nouveau, rien ne change pour l'existant.

Déjà décidé

  • Actions de ligne : deux contrôles au plus, à droite, visibles au survol, au focus et sur la ligne sélectionnée ; clic droit et Maj+F10 ouvrent le menu « … » (D-066, D-053).
  • Barre du haut : boutons-icônes uniquement (spec AppShell, option actions). P13 traitera l'action à texte et le repli dans la barre du haut.
  • Élément danger du menu : rouge, en dernier, après un séparateur ; son clic ouvre une confirmation (D-049, D-007).
  • Confirmation seulement pour l'irréversible (D-007, principe 4).
  • Un bouton-icône n'a ni chargement, ni couleur danger (spec IconButton, Exclus).
  • État vide : icône, titre, phrase et action principale (layout-rules, ListPage).
  • Vues d'une page : dans les onglets, pas en bascule de boutons (D-021).
  • Button : primary monochrome, secondary sur fond --field, chargement isPending ; IconButton isPending (D-102, D-103, D-105, D-107).
  • Libellés internes (« Plus d'actions », question par défaut) dans messages (D-089).

À décider (tout est tranché)

  1. Zones et règle : six zones (topbar, header, toolbar, section, row, empty), avec la règle du tableau ci-dessous. Ordre dans une barre : icônes, « … », action principale à droite. validé D-111
  2. Barre du haut : A l'action principale devient la première icône (spec AppShell actuelle) ; B elle s'affiche en texte (change AppShell, c'est P13). A validé D-112
  3. Section : A l'action principale en bouton secondaire ; B en bouton principal plein. A validé D-113
  4. Ligne : A une icône, puis « … » s'il reste des actions (deux contrôles, D-066) ; B deux icônes, puis « … » (trois contrôles). A validé D-114
  5. Danger : A dans « … », en dernier, après un séparateur, sans titre (D-049) ; B sous un titre « Actions définitives ». A validé D-115
  6. Exécution : A ActionBar confirme, montre l'attente et rend l'erreur à onError ; les notifications restent au gabarit (P6). B ActionBar affiche aussi les notifications de réussite et d'échec. A validé D-116
  7. Petit écran (sous 640 px) : les icônes passent dans « … », l'action principale reste en texte. validé D-117
  8. Champs du modèle : id, label, icon?, onPress, primary?, danger?, confirm?, shortcut?, isDisabled?, isHidden?. Exclus : bascule de vue (group, selected), message de réussite. validé D-110
  9. Attente sur une icône : le bouton-icône prend l'état isPending que P1 ajoute à IconButton (D-107) : roue, focus gardé, aria-busy. Une entrée de menu ferme le menu tout de suite. validé D-118
    La question posait A « désactivé + aria-busy » parce que IconButton n'avait pas de chargement. P1 l'a ajouté le même jour (D-107) : une seule règle d'attente reste.

Dans l'app — une liste de documents

À essayer : survolez une ligne ; ouvrez « … » à la souris ou au clavier ; clic droit sur une ligne ; « Exporter en CSV » attend 1,5 s (roue du bouton-icône, D-107, D-118) ; « Supprimer » ouvre la confirmation ; en état « Échec », l'erreur remonte à onError et le gabarit affiche la notification. La confirmation et la notification sont des maquettes de P3 et de P6.

Avant et après, côté app

Avant : la page pose ses boutons

<IconButton icon={<Download/>} label="Exporter en CSV" onPress={exporter}/>
<Menu trigger={<IconButton icon={<More/>} label="Plus d'actions"/>}>
  <Menu.Item label="Importer un fichier…" onAction={importer}/>
  <Menu.Separator/>
  <Menu.Item danger label="Supprimer les archivés"
    onAction={() => demanderPuisSupprimer()}/>

Après : la page décrit ses actions

const actions: Action[] = [
  { id: "new", label: "Nouveau document", icon: <Plus/>,
    primary: true, onPress: creer },
  { id: "export", label: "Exporter en CSV", icon: <Download/>,
    onPress: () => api.export() },          // promesse : attente
  { id: "import", label: "Importer un fichier…", onPress: importer },
  { id: "purge", label: "Supprimer les archivés", danger: true,
    confirm: { title: "Supprimer les 12 documents archivés ?",
               message: "Cette action est définitive." },
    onPress: () => api.purge() },
];
<ActionBar zone="header" actions={actions} onError={notifier}/>
