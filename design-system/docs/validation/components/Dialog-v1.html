Dialog et confirmation — v1 VALIDÉ le 2026-11-23

Mode propose, besoin venu d'Alfred (P3). Nouveau composant Dialog et nouveau hook useConfirm. Version mineure : rien d'existant ne change. Spec à écrire : src/components/Dialog/Dialog.spec.md.

Déjà décidé

  • Une modale flotte : surface --surface-raised, ombre, rayon de 12 px (D-040, layout-rules).
  • Ouverture en 260 ms (dur-slow), rien ne bouge si l'utilisateur réduit les animations (D-014).
  • Échap ferme ce qui flotte, le plus haut d'abord (layout-rules).
  • Les Réglages s'ouvrent dans une grande modale sur bureau et tablette, en plein écran sur mobile (D-015). AppShell renvoie vers Dialog pour toute fenêtre secondaire.
  • Confirmation seulement pour l'irréversible ; sinon, annulation possible (D-007).
  • React Aria gère le piège du focus, le retour du focus au déclencheur et le blocage du défilement de la page (D-008).
  • Le × est un IconButton (D-035 à D-037). Les libellés internes (« Fermer », « Annuler ») viennent de messages (D-089).
  • Les boutons du pied sont des Button (D-100 à D-105) : principale monochrome, danger en rouge plein, chargement avec roue.

À décider

  1. Tailles : A quatre largeurs fixes sm 400, md 560 (défaut), lg 800, xl 1080 × 720 avec un corps sans marge pour un gabarit (Réglages) ; B largeur au contenu (320 à 800 px), plus xl ; C deux largeurs, 480 et 880. validé : A
  2. Petit écran (≤ 640 px) : A feuille qui monte du bas, pour toutes ; B sm et md centrées avec 16 px de marge, lg et xl en plein écran ; C tout en plein écran. validé : B
  3. Clic hors de la modale : A ferme toujours ; B ferme, sauf si une saisie a commencé (la modale fait alors un court rebond) ; C ne ferme jamais. validé : B
  4. Traits sous l'en-tête et au-dessus du pied : A toujours ; B seulement quand le corps défile. validé : B
  5. Ordre des boutons du pied : A le même partout, calé à droite : « Annuler », puis l'action principale ; B selon le système (principale à gauche sous Windows). validé : A
  6. Focus à l'ouverture : A l'élément marqué autoFocus, sinon le premier champ du corps, sinon la modale elle-même ; confirmation : « Annuler » ; B le premier élément focusable (souvent le ×) ; C l'action principale. validé : A
  7. Apparence de la confirmation : A titre, phrase et deux boutons, sans × ni icône, le bouton rouge porte le danger ; B la même avec une icône d'alerte rouge ; C une Dialog sm ordinaire, avec ×. validé : A
  8. Où vit la confirmation : A SocleProvider l'affiche, useConfirm() renvoie seulement confirm ; B le hook renvoie aussi un élément que l'app doit placer. validé : A
  9. Action longue après « Supprimer » : A la confirmation se ferme tout de suite, la suite se montre ailleurs (notification) ; B option onConfirm asynchrone : la confirmation reste ouverte avec le bouton en chargement, rien ne la ferme, et une erreur s'affiche sur place. Sans onConfirm, comportement A. validé : B

API proposée

Dialog

Pilotée par l'app. Le titre est obligatoire (nom accessible).

<Dialog
  isOpen={open}
  onOpenChange={setOpen}
  title="Nouveau projet"
  description="Il sera visible par l'équipe."
  size="md"            // sm | md | lg | xl
  isBusy={saving}      // rien ne la ferme
  footer={<>
    <Button onPress={close}>Annuler</Button>
    <Button variant="primary"
      onPress={save}>Créer</Button>
  </>}
>
  …champs…
</Dialog>

useConfirm

Remplace window.confirm. Résout true ou false.

const confirm = useConfirm();

const ok = await confirm({
  title: "Supprimer « Atelier » ?",
  message: "Le projet et ses 12 tâches
    seront supprimés.",
  confirmLabel: "Supprimer",
  // danger: true par défaut
  // onConfirm: () => api.remove(id)
});

Exclus de la v1

Pas de modale non bloquante (prendre un Popover ou le panneau de détail).
Pas de position libre ni de glisser.
Pas de saisie du nom pour confirmer.
Pas de className ni de style.
Pas de pied sans le × (le × est toujours là, sauf en confirmation).
Quand le modèle Action (P2) sera validé, footer pourra accepter une liste d'actions, et Action.confirm pourra appeler useConfirm.

Projets

À jouer : ouvrez une modale, essayez Échap, Tab et Maj+Tab, un clic sur le fond (avant et après avoir tapé dans un champ). La corbeille d'une ligne ouvre la confirmation. Dans les Réglages, « Supprimer l'espace » ouvre une confirmation par-dessus la modale : Échap ne ferme que la plus haute.

Hôte de la confirmation (question 8) : rien ne se voit à l'écran. Avec A, l'app n'a rien à placer ; avec B, chaque écran qui confirme doit rendre {confirmDialog}.
