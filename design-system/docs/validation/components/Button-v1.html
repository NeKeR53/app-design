Button — v1 VALIDÉ le 2026-11-23

Mode propose "Button à texte", depuis Alfred. Spec : src/components/Button/Button.spec.md. Remplace dans Alfred Button.tsx, primitives/button.tsx et RefreshButton.tsx. Impact : version mineure (nouveau composant, nouveau token --danger-fg).

Test du générique

Oui : toute app a besoin d'un bouton à texte (envoyer un formulaire, confirmer, annuler, réessayer). Rien de métier.

Déjà décidé

  • Rayon 8 px, comme tout contrôle (D-040) ; focus : anneau --accent de 2 px.
  • Transitions de couleur ≤ 120 ms (D-014) ; icône de 16 px en currentColor (D-011).
  • Pied de section du panneau de détail : un Button (D-059), rendu validé de 26 px sur fond --field.
  • IconButton reste le bouton sans libellé, sans couleur ni danger (D-037).
  • Une action principale au plus par zone (layout-rules, ListPage et FormPage).
  • Pas de className ni de style, comme les autres composants.

Proposé sans question (dites-le si un point ne va pas)

  • API : <Button variant icon size isPending isDisabled onPress type form aria-label autoFocus>Libellé</Button>. Le libellé est un texte (children: string). Toutes les options sont facultatives ; variant vaut "secondary" par défaut.
  • Discrète : fond transparent, texte --fg-2 ; au survol, fond --hover et texte --fg. Même logique que IconButton.
  • Texte en --fw-medium, sur une ligne, jamais tronqué : la largeur suit le libellé. Pas de pleine largeur dans cette version.
  • aria-label facultatif : il complète le libellé visible quand il est ambigu (« Approuver Projet X »). Il doit commencer par le libellé visible (WCAG 2.5.3).
  • Désactivé : opacité 40 %, ni survol ni action. Boutons voisins espacés de 8 px.

À décider — tranché le 2026-11-23 (D-100 à D-107)

  1. Hauteur : la hauteur normale suit --row-h (34 px web, 28 px desktop), comme un champ. Faut-il aussi une taille size="sm" (26 px web, 24 px desktop) pour le pied de section du panneau de détail et les zones denses ? Validé : oui — le rendu de 26 px est déjà validé (D-059) et 24 px reste la cible minimale.
  2. Principale : A monochrome inversé (fond --fg) ; B couleur d'accent. Validé : A — le principe « monochrome » réserve l'accent au sens (sélection, lien, non-lu).
  3. Secondaire : A fond --field sans contour ; B fond --surface et contour --line-strong (Alfred aujourd'hui). Validé : A — même rendu que le pied de section validé, et pas de trait décoratif.
  4. Danger : A rouge plein ; B texte rouge sur fond --field ; C contour rouge (Alfred). Validé : A — IconButton dit déjà que « c'est la confirmation qui est en rouge » : le bouton qui exécute doit se voir. A demande un nouveau token --danger-fg (texte sombre sur le rouge clair du mode sombre, contraste AA).
  5. Chargement (isPending) : A une roue remplace l'icône (ou se place devant le libellé), le libellé reste ; B la roue seule au centre, le libellé est caché. Dans les deux cas, la largeur ne change pas (précision au codage : sans icône, A élargit le bouton de la place de la roue, comme le montre la démo), le bouton garde le focus, ignore les clics, et le lecteur d'écran annonce l'attente. Validé : A — le libellé reste lisible ; le loadingLabel d'Alfred (« Enregistrement… ») change la largeur et n'est pas repris.
  6. Icône : au début seulement, ou aussi en fin (flèche, chevron) ? Validé : au début seulement — un chevron de menu est le rôle du déclencheur de Menu, pas du bouton.
  7. « Actualiser » (RefreshButton) : A IconButton gagne isPending (l'icône devient une roue) ; B un Button discret « Actualiser » avec icône. Validé : A — la barre d'outils n'accepte que des boutons-icônes, et Alfred montre l'attente sur 6 de ses 8 boutons « Actualiser ». Cela retire une exclusion de la spec IconButton (option facultative, version mineure).
