Notifications — v1 VALIDÉ le 2026-11-23

Mode propose, depuis Alfred (proposition P6). Deux briques : les toasts éphémères et le centre de notifications de la barre du haut. Specs à créer : src/components/Toast/Toast.spec.md et src/patterns/NotificationCenter/NotificationCenter.spec.md. Version mineure : tout est nouveau et facultatif.

Test du générique

Réussi. Toute app de travail confirme une action (« Document archivé »), propose de l'annuler (D-007) et garde la trace d'événements passés (une tâche finie, un import en échec). Rien n'est propre à Alfred : les libellés, les sources et les actions viennent de l'app.

Avant (Alfred aujourd'hui)

  • Toasts par la librairie sonner, restylée par 70 lignes de CSS ; en bas à droite ; 4 visibles.
  • Tons info, succès, alerte, erreur ; 5 s, 8 s pour alerte et erreur ; deux actions au plus.
  • Cloche dans la barre du haut : nombre de non-lus (« 9+ »), panneau ancré, « Tout effacer ». Ouvrir marque tout comme lu.
  • FeedbackBanner : message persistant, en cadre (contained) ou en bandeau pleine largeur (bar).

Déjà décidé

  • Confirmation seulement pour l'irréversible ; le reste agit tout de suite et s'annule depuis une notification (D-007).
  • Ce qui flotte porte une ombre, sur --surface-raised (principes, D-012).
  • Monochrome : la couleur ne porte que du sens ; le non-lu est un point --accent (D-001, D-044).
  • Rayons : 8 px pour un contrôle, 12 px pour un conteneur (D-040).
  • La barre du haut ne reçoit que des boutons-icônes (AppShell, slot actions).
  • Échap ferme ce qui flotte. Libellés internes par messages (D-089).
  • Brief : un état de page se signale dans la barre du haut, jamais par un bandeau pleine largeur.

API proposée (toutes les options sont facultatives)

// Une seule file par app, utilisable hors de React.
const notifications = createNotifications();
<SocleProvider notifications={notifications}>…

notifications.notify({
  tone: "success",            // success | info | warning | danger
  title: "Document archivé",
  description: "Budget 2027",
  action: { label: "Annuler", onAction: restore },
  duration: 8000,              // ms ; null : jusqu'à fermeture
  source: "Import",            // affichée dans le centre
  history: true,               // false : toast seul, hors du centre
  toast: true,                 // false : centre seul, sans toast
});
const notify = useNotify();    // même fonction, dans React

// Barre du haut :
<AppShell actions={<NotificationCenter />} …/>

À décider — tout validé le 2026-11-23, par délégation de l'utilisateur (recommandations retenues)

  1. Moteur : A garder sonner (nouvelle dépendance, restylée) ; B React Aria Toast, déjà dans nos dépendances (file, minuterie, pause, F6 vers la région, focus rendu à la fermeture), enveloppé par Socle ; C tout écrire nous-mêmes. validé (D-150)
  2. Apparence du toast : A carte neutre --surface-raised, seule l'icône porte le ton ; B fond teinté par le ton ; C sombre constant, comme l'info-bulle. validé (D-151)
  3. Tons : 3 (succès, info, erreur) ou 4 avec « alerte » (--warning existe, Alfred s'en sert). validé (D-152)
  4. Durée : 5 s par défaut ; 8 s avec une action ; une erreur reste jusqu'à sa fermeture ; pause au survol, au focus et quand la fenêtre perd le focus ; duration réglable par appel, 5 s au minimum. validé (D-153)
  5. Pile : 3 toasts visibles au plus, le plus récent en bas ; au-delà, le plus ancien se ferme (il reste dans le centre). validé (D-154)
  6. Action : une seule action texte, plus la croix de fermeture ; l'action ferme le toast. validé (D-155)
  7. Lien toast ↔ centre : par défaut, chaque notification va dans les deux ; history: false pour une confirmation triviale (« Lien copié ») ; toast: false pour un événement de fond. validé (D-156)
  8. Action dans le centre : l'action du toast (« Annuler ») expire avec lui et n'est pas reprise dans le centre ; une ligne du centre peut s'ouvrir (option onOpen). validé (D-156)
  9. Compteur : A pastille --accent avec le nombre de non-lus, « 9+ » au-delà ; B simple point. validé (D-157)
  10. Ouverture du centre : panneau ancré sous la cloche (380 px), plein écran sur mobile ; l'ouvrir marque tout comme lu, mais les points restent jusqu'à la fermeture. validé (D-157)
  11. Contenu du centre : groupes « Aujourd'hui », « Hier », puis la date ; ligne = icône du ton, titre, texte, heure · source, point non-lu ; × au survol pour retirer ; en-tête « Tout effacer » ; état vide. validé (D-158)
  12. Persistance : en mémoire, 100 notifications au plus ; la persistance entre deux ouvertures reste à l'app (initial et onChange de la file). validé (D-158)
  13. Avenir de FeedbackBanner : plus de bandeau pleine largeur. Un état durable de page (hors ligne, lecture seule) va dans la barre du haut, en indicateur compact ; un message local reste un encart dans le contenu (comme D-085). Ici, on écrit la règle dans layout-rules.md ; l'indicateur et l'encart feront chacun une proposition à part. validé (D-159)
