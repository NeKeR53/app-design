DocumentViewer et HtmlContent VALIDÉ le 2026-11-23

Deux composants d'affichage de contenu reçu : l'aperçu d'un document (PDF par pdf.js, image) et le HTML venu de l'extérieur (courriel, page). Validation par délégation de l'utilisateur, 2026-11-23. Décisions D-310 à D-319.

  • Chargement par SkeletonGroup, affiché après 200 ms (D-165).
  • Erreur et format inconnu par EmptyState compact (D-166).
  • Libellés internes traduisibles par messages (D-089).
  • Actions de l'app par le modèle Action, zone toolbar (D-110, D-111).
  • Pas de couleur en dur hors tokens (D-009).

Tranché (par délégation, recommandations retenues)

  1. pdf.js : peer dependency facultative, chargée par l'app (loadPdf) — option A ci-dessous (D-311).
  2. Formats : PDF et image ; tout autre format → « Format non pris en charge » avec « Télécharger » (D-310).
  3. Barre : position ou nom, page précédente/suivante, zoom −/%/+, « Ajuster à la largeur », « Télécharger » (D-312).
  4. Page du document sur un fond « papier » blanc dans les deux thèmes : tokens --paper, --paper-fg, --paper-link (D-315).
  5. HtmlContent : racine fantôme + liste blanche, pas d'iframe — option A (D-317).
  6. HtmlContent sur papier par défaut ; surface="theme" pour un HTML simple produit par l'app — option A (D-319).

Options comparées

pdf.js — A. Chargé par l'app retenu

Socle n'importe jamais pdf.js. L'app passe loadPdf={() => import("pdfjs-dist")} et règle elle-même le worker (faux worker si le cadre l'interdit). Peer dependency facultative : une app sans PDF n'installe rien.

pdf.js — B. Import dynamique dans Socle

Plus simple à l'usage, mais le bundler de chaque app doit résoudre pdfjs-dist même sans PDF ; le réglage du worker devient le problème de Socle.

pdf.js — C. Dépendance directe

~1,7 Mo pour toutes les apps ; version imposée. Écartée.

Isolation — A. Racine fantôme + liste blanche retenu

Hauteur naturelle, marche dans un cadre qui interdit les iframes. contain: content garde un élément « fixed » dans la zone.

Isolation — B. iframe sandbox

Isolation la plus forte, mais hauteur à mesurer, focus et liens plus lourds, interdite par la CSP de certains hôtes (Alfred). Écartée.

Surface HTML — A. Papier par défaut retenu

Un courriel a ses propres couleurs (texte noir en dur) : sur papier, il reste lisible en sombre. surface="theme" pour un HTML simple.

Comportements (jouables ci-dessus, détaillés dans les specs)

DocumentViewer

  • Ouverture : ajusté à la largeur. Une image n'est jamais agrandie au-delà de 100 % en mode ajusté.
  • Zoom par paliers 25 à 400 % ; Ctrl ou ⌘ + molette autour du pointeur ; Ctrl/⌘ + « + », « − », « 0 » (ajuster) quand le focus est dans la visionneuse.
  • Pages dessinées à l'approche de la zone visible ; le dessin précédent reste pendant un zoom.
  • « Page n / N » suit la page en haut de la zone ; précédente/suivante y font défiler.
  • Zone de défilement focusable : flèches, Page préc./suiv. défilent.

HtmlContent

  • Aucun script, formulaire, cadre, SVG, on…, javascript: ; styles sans url(), @import, :host.
  • Images distantes masquées : bandeau « N images masquées » + « Afficher les images ». Images intégrées (data:) affichées ; cid: via resolveImage.
  • Liens http, https, mailto : clic ou Entrée → onLink(url) ; l'adresse s'affiche au survol. Sans onLink : texte simple.
