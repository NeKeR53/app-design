Options écartées, côte à côte

1A — API déclarative typée retenue

L'app décrit groups → items → sections → settings ; sept types (switch, select, text, action, item, info) et un contenu libre de section pour une Table. Le rendu reste uniforme dans toutes les apps.

1B — Composants à assembler

<SettingsPage.Nav>, <SettingRow>… plus souple, mais chaque app recompose les lignes et dérive vite. Écartée.

2B — Texte : boutons « Annuler / Enregistrer »

Le rendu d'Alfred. Deux clics de plus et une ligne qui bouge. Écartée au profit de 2A (Entrée, sortie du champ, Échap rétablit).

3B — Corbeille rouge visible sur la ligne

Rendu d'Alfred. Contraire à D-115 (danger dans « … »). Écartée : la corbeille passe dans « … », en dernier, confirmée.

4B — Contrôle segmenté pour 2–3 choix

Demande un nouveau composant (SegmentedControl) hors de ce besoin. Écartée pour l'instant : Select partout ; à proposer à part si plusieurs apps le demandent.

5B — Bascule mobile d'après l'écran

Une requête média ignore la taille du conteneur. Écartée : requête de conteneur sur le gabarit (640 px), qui marche dans la modale comme en pleine page.
